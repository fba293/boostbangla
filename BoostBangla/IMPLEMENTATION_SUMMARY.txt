================================================================================
🔄 ORDER PROCESSING FLOW
================================================================================

1. User fills form & clicks "Place Order"
   ↓
2. Frontend validates & sends to /php/order-handler.php
   ↓
3. Backend checks: order data → user balance
   ↓
4. Store order locally with status "pending"
   ↓
5. Deduct money from user wallet
   ↓
6. Forward order to AmarBoost API
   ↓
7. AmarBoost returns order ID
   ↓
8. Link AmarBoost ID to local order, update status "processing"
   ↓
9. Return confirmation to user
   ↓
10. Cron job (every 5 min): Get status from AmarBoost → Update local DB
   ↓
11. Orders marked as completed, profit logged
   ↓
12. Daily summary: Calculate total profit, revenue, costs

📈 WHAT YOU CAN MONITOR

REAL-TIME:

HISTORICAL:

- User spending: SELECT user_id, SUM(user_price) FROM orders GROUP BY user_id;

DIAGNOSTICS:

- Sync status: ps aux | grep sync-engine.php

================================================================================
📞 TROUBLESHOOTING
================================================================================

Database Connection Error:
→ Check MySQL is running
→ Verify credentials in .env
→ Test: mysql -u root -p boostbangla -e "SELECT 1;"

Orders Not Syncing:
→ Check cron is running: ps aux | grep sync-engine
→ Manually trigger: php public/php/sync-engine.php sync
→ Check logs: tail -f public/php/logs/api_proxy_*.log

Balance Not Deducting:
→ Check order_transactions table
→ Verify user_wallets has entry for user
→ Check for errors in logs

High Processing Fees:
→ Verify PROFIT_MARGIN setting
→ Check calculatePricing() logic
→ Review profit_summary for calculations
